# ugame-client

Unity-клиент для [ugame-server](../ugame-server): гостевой вход, регистрация, поиск матча и сам матч.

## Запуск

1. Запустите сервер: `docker compose up -d`, затем `meta-service` и `game-server` (см. README сервера).
2. Откройте этот проект в Unity 6. При первой загрузке редактор сам создаст сцены `Menu` и `Game`
   и поставит их в список сцен сборки (или меню **UGame → Создать сцены**).
3. Нажмите **Play** — игра всегда стартует со сцены `Menu`, какая бы сцена ни была открыта.
4. Клиент сам войдёт гостем и покажет лобби. Нажмите «Играть».

**Сервер.** По умолчанию `http://193.238.44.107:8888`. Если он не отвечает, по центру экрана
появится выбор другого сервера; выбранный запоминается. Сменить сервер можно и из лобби.

**Аккаунт.** При первом запуске сервер создаёт гостевой аккаунт со сгенерированными именем
(`Player_123456`) и паролем — клиент хранит их у себя и входит ими автоматически. В лобби гость
может «Зарегистрироваться» (своё имя, email, пароль — кубки и статистика сохраняются) или
«Войти в аккаунт». У зарегистрированного игрока на устройстве хранится refresh-токен, а не пароль;
«Выйти из аккаунта» возвращает к гостю. Данные входа хранятся отдельно для каждого сервера.

По умолчанию матч собирается из **2 игроков** (`UGAME_PLAYERS_PER_MATCH` в meta-service).
Чтобы сыграть одному, запустите meta-service с `UGAME_PLAYERS_PER_MATCH=1`. Для двух клиентов:
- соберите игру (*File → Build Profiles → Build*) и запустите сборку рядом с редактором, или
- поставьте пакет **Multiplayer Play Mode** (Window → Package Manager) — он запускает дополнительных
  игроков прямо из редактора.

Каждый клиент должен войти под своим аккаунтом. Сборка и редактор на одном компьютере делят
PlayerPrefs — во втором клиенте войдите в другой аккаунт («Войти в аккаунт»).

**Управление на компьютере:** WASD — движение, мышь — прицел, ЛКМ или пробел — выстрел (удержание — очередь).

**Управление на телефоне** (в стиле Brawl Stars):
- левая половина экрана — джойстик движения, появляется там, где коснулись;
- правая половина — джойстик атаки: тяните, чтобы прицелиться (на земле видна линия выстрела),
  отпустите — выстрел; вернули палец в центр и отпустили — выстрел отменён;
- короткое касание справа — выстрел с автоприцелом в ближайшего врага (до 10 м);
- пока не целитесь, боец смотрит туда, куда идёт.

Проверить без телефона: окно **Game → Simulator** (Device Simulator) — клиент считает его телефоном
и включает джойстики; мышь работает как палец.

## Игра с телефона

Телефон и компьютер с сервером должны быть в одной Wi-Fi сети.

1. Узнайте IP компьютера (`ipconfig` → IPv4, например `192.168.1.10`).
2. Игровой сервер должен сообщать клиентам этот адрес, а не `127.0.0.1`:
   запустите game-server с `UGAME_SERVER_PUBLIC_HOST=192.168.1.10`.
3. Разрешите в брандмауэре Windows входящие **TCP 8080** (meta-service) и **UDP 7777** (game-server).
4. Соберите клиент под Android (*File → Build Profiles → Android → Build and Run*).
5. В лобби нажмите «Сменить» рядом с адресом сервера и укажите `http://192.168.1.10:8080`.

## Устройство

| Файл | Что делает |
|---|---|
| `Scripts/Game/GameClient.cs` | сессия, живущая между сценами: сервер, аккаунт, соединение с матчем, FPS и ping |
| `Scripts/Game/MenuController.cs` | сцена Menu: выбор сервера, вход, лобби, регистрация, поиск матча (IMGUI) |
| `Scripts/Game/GameController.cs` | сцена Game: матч, счёт, итоги |
| `Scripts/Game/AccountStore.cs` | данные входа на устройстве (PlayerPrefs), отдельно для каждого сервера |
| `Scripts/Game/Ui.cs` | общие стили и масштаб интерфейса |
| `Scripts/Game/MatchView*.cs` | матч: ввод, предсказание своего бойца и выстрелов, интерполяция чужих, сцена и камера, здоровье, интерфейс — по файлу на задачу (список в начале `MatchView.cs`) |
| `Scripts/Game/GameRules.cs` | правила игры (скорости, радиусы, кулдауны) — копия констант сервера |
| `Scripts/Game/InputReader.cs` | клавиатура и мышь (новая Input System, с запасным вариантом для старой) |
| `Scripts/Game/TouchControls.cs` | сенсорные джойстики для телефонов |
| `Scripts/Net/MetaApi.cs` | HTTP к meta-service: `/api/auth/*`, `/api/me`, `/api/matchmaking/*`; сам обновляет истёкший JWT |
| `Scripts/Net/GameConnection.cs` | UDP-соединение с game-server через kcp2k |
| `Scripts/Net/Protocol.cs` | ручная бинарная упаковка ввода и снапшотов — зеркало Java-модуля `protocol` |
| `Scripts/Net/ProtoMessages.cs` | надёжные сообщения из `game.proto` и минимальный кодировщик protobuf |
| `Plugins/kcp2k` | исходники [kcp2k](https://github.com/MirrorNetworking/kcp2k) v1.41 (MIT) |
| `Editor/UGameProjectSetup.cs` | разрешает `http://` и Run In Background в настройках проекта |
| `Editor/UGameSceneSetup.cs` | создаёт сцены Menu и Game, список сцен сборки, старт Play со сцены Menu |

**Сетевая модель.** Сервер авторитарный. Клиент 30 раз в секунду отправляет ввод (в каждом пакете —
четыре последние команды, так что потеря пакета не теряет нажатие).
- *Свой боец* двигается сразу (client-side prediction). Когда приходит снапшот, клиент берёт позицию
  сервера и заново применяет ещё не подтверждённые команды; расхождение плавно сглаживается.
  Формула движения в `MatchView.Step` должна совпадать с `World.moveBrawler` на сервере, а константы
  `GameRules.cs` — с `World.java` и `ShotType.java`.
- *Чужие бойцы и снаряды* показываются с задержкой ~100 мс и интерполируются между снапшотами.

**Цвета.** Тело бойца — свой цвет из палитры (по id сущности). Кольцо под ногами — команда:
синее у союзников, красное у врагов. Над головой — имя («Вы» — жёлтым) и полоска здоровья.
Команда 1 появляется сверху арены, поэтому её камера развёрнута на 180°: у каждого игрока враги
наверху экрана.

## Что учесть

- **HTTP без TLS** разрешён только ради локального сервера. Для релиза поставьте meta-service за HTTPS
  и верните *Player Settings → Allow downloads over HTTP* в «Not Allowed».
- **Protobuf.** Вместо пакета Google.Protobuf — свой кодировщик на ~200 строк: сообщений всего семь.
  Если `game.proto` разрастётся, проще подключить Google.Protobuf и генерировать классы `protoc`.
- **Интерфейс на IMGUI** — чтобы всё работало без настройки сцены. Для релиза экраны лучше перенести
  на UI Toolkit; логика переходов в `GameClient` от этого не изменится.
