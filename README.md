# ugame-client

Unity-клиент для [ugame-server](../ugame-server): регистрация, вход, поиск матча и сам матч.

## Запуск

1. Запустите сервер: `docker compose up -d`, затем `meta-service` и `game-server` (см. README сервера).
2. Откройте этот проект в Unity 6 и нажмите **Play** в любой сцене — клиент создаётся сам
   (`GameClient.Bootstrap`), сцены и префабы настраивать не нужно.
3. Зарегистрируйтесь, нажмите «Играть».

По умолчанию матч собирается из **2 игроков** (`UGAME_PLAYERS_PER_MATCH` в meta-service).
Чтобы сыграть одному, запустите meta-service с `UGAME_PLAYERS_PER_MATCH=1`. Для двух клиентов:
- соберите игру (*File → Build Profiles → Build*) и запустите сборку рядом с редактором, или
- поставьте пакет **Multiplayer Play Mode** (Window → Package Manager) — он запускает дополнительных
  игроков прямо из редактора.

Каждый клиент должен войти под своим аккаунтом.

**Управление:** WASD — движение, мышь — прицел, ЛКМ или пробел — выстрел (удержание — очередь).

## Устройство

| Файл | Что делает |
|---|---|
| `Scripts/Game/GameClient.cs` | экраны (вход, регистрация, лобби, поиск, матч, итоги) и переходы между ними; интерфейс на IMGUI |
| `Scripts/Game/MatchView.cs` | зелёная арена 20×30 м, разноцветные бойцы, снаряды, камера, полоски здоровья |
| `Scripts/Game/InputReader.cs` | клавиатура и мышь (новая Input System, с запасным вариантом для старой) |
| `Scripts/Net/MetaApi.cs` | HTTP к meta-service: `/api/auth/*`, `/api/me`, `/api/matchmaking/*`; сам обновляет истёкший JWT |
| `Scripts/Net/GameConnection.cs` | UDP-соединение с game-server через kcp2k |
| `Scripts/Net/Protocol.cs` | ручная бинарная упаковка ввода и снапшотов — зеркало Java-модуля `protocol` |
| `Scripts/Net/ProtoMessages.cs` | надёжные сообщения из `game.proto` и минимальный кодировщик protobuf |
| `Plugins/kcp2k` | исходники [kcp2k](https://github.com/MirrorNetworking/kcp2k) v1.41 (MIT) |
| `Editor/UGameProjectSetup.cs` | разрешает `http://` и Run In Background в настройках проекта |

**Сетевая модель.** Сервер авторитарный. Клиент 30 раз в секунду отправляет ввод (в каждом пакете —
четыре последние команды, так что потеря пакета не теряет нажатие).
- *Свой боец* двигается сразу (client-side prediction). Когда приходит снапшот, клиент берёт позицию
  сервера и заново применяет ещё не подтверждённые команды; расхождение плавно сглаживается.
  Формула движения в `MatchView.Step` должна совпадать с `World.moveBrawler` на сервере.
- *Чужие бойцы и снаряды* показываются с задержкой ~100 мс и интерполируются между снапшотами.

**Цвета.** Тело бойца — свой цвет из палитры (по id сущности). Кольцо под ногами — команда:
синее у союзников, красное у врагов. Над головой — имя («Вы» — жёлтым) и полоска здоровья.
Команда 1 появляется сверху арены, поэтому её камера развёрнута на 180°: у каждого игрока враги
наверху экрана.

## Что учесть

- **HTTP без TLS** разрешён только ради локального сервера. Для релиза поставьте meta-service за HTTPS
  и верните *Player Settings → Allow downloads over HTTP* в «Not Allowed».
- **Protobuf.** Вместо пакета Google.Protobuf — свой кодировщик на ~200 строк: сообщений всего семь.
  Если `game.proto` разрастётся, проще подключить Google.Protobuf и генерировать классы `protoc`.
- **Интерфейс на IMGUI** — чтобы всё работало без настройки сцены. Для релиза экраны лучше перенести
  на UI Toolkit; логика переходов в `GameClient` от этого не изменится.
